# Security Policy

## Reporting a Vulnerability

The security of CLARY and its users is important to us.

If you discover a security vulnerability in CLARY, please report it responsibly so that we can investigate and address it.

**Please do not report security vulnerabilities through public GitHub Issues or public Pull Requests.**

Instead, use GitHub's **Private Vulnerability Reporting** feature:

1. Visit the [CLARY GitHub repository](https://github.com/GKPROEJECT/CLARY).
2. Open the **Security** tab.
3. Select **Report a vulnerability**.
4. Submit a private report with as much detail as possible.

## What to Include in Your Report

Please include the following information whenever possible:

- A clear description of the vulnerability.
- The affected component or feature.
- The steps required to reproduce the issue.
- The potential security impact.
- The affected CLARY version.
- Any proof of concept or supporting information.

Please do not include real passwords, access tokens, private keys, or other sensitive user data in your report.

## Responsible Disclosure

Please allow the CLARY maintainers reasonable time to investigate and address a reported vulnerability before disclosing it publicly.

We ask security researchers not to publicly disclose vulnerability details until a fix or an appropriate mitigation is available.

## Scope

This policy applies to the CLARY application, its source code, and components maintained within this repository.

Third-party services and dependencies may have their own security reporting procedures.

## Security Updates

Security fixes and relevant updates will be distributed through the official CLARY project channels and releases when available.

Users are encouraged to keep CLARY updated to the latest available version.

## Acknowledgements

We appreciate the work of security researchers who help improve CLARY by responsibly reporting vulnerabilities.
